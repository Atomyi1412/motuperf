# MoTuPerf 跨平台桌面版实现方案

状态：confirmed

## 技术路线

- UI：`.NET 8 + Avalonia`。
- 首期平台：Windows `win-x64`、Apple Silicon macOS `osx-arm64`。
- 共享：模型、指标统计、采集 JSONL、设备/进程逻辑、session 和 CSV。
- 平台适配：运行时路径、数据目录、文件对话框、USB 前置条件、图标和安装包。
- 旧版保护：WPF `v0.4.65` 工程和备份保持独立可用。

## 实现顺序

1. 新建 solution 和共享 Core/Platform。
2. 建立 Avalonia 主工作台和设备选择。
3. 接通真实采集，再迁移全部图表和截图。
4. 抽取 session/CSV，验证历史文件兼容。
5. 发布并验收 Windows 跨平台版。
6. 在 M 系列 Mac 上构建 arm64 运行时、`.app` 和安装包，完成真机验收。

## 验证原则

- 每次共享代码调整同时验证旧 WPF 和新 Avalonia。
- UI 必须实际启动并截图检查，不能只看 build 结果。
- Windows 交叉发布 `osx-arm64` 只证明托管代码可生成，不证明 macOS 可用。
- macOS 完成前必须有 M 系列真机、USB 设备和安装包运行证据。

## iOS 截图方向修复

- 每次 iOS 截图同时查询 SpringBoard `InterfaceOrientation`，按 `0=未知、1=竖屏、2=倒置竖屏、3=Home 键在右的横屏、4=Home 键在左的横屏` 写入截图模型；方向查询失败只回退未知，不得让截图或采集中止。
- 方向从 `ScreenshotInfo` 传入 `SessionScreenshot`，保存和打开 `.motuperf` 后保持不变；旧现场缺少字段时默认 `0`。
- 展示层只在方向为 `3/4` 且 PNG 像素仍为竖向画布时生成内存显示副本：`3` 逆时针、`4` 顺时针；PNG 已经是宽图时禁止重复旋转。v0.21.2 修正此前正负方向颠倒的映射，以不对称像素图案和真实游戏文字核对上下方向。
- 缩略图、大图、上一张/下一张使用同一方向投影；窗口尺寸和适应缩放按旋转后的显示尺寸计算。
- 自动测试覆盖方向解析、竖屏/横屏/未知回退、宽图不重复旋转和现场文件方向往返；真实 iOS 横屏仍需在设备上确认两种横屏方向。

## v0.21.3 六项审查修复

- 主动迁移采用完整复制、校验源/目标、原子提交目录配置、清理未变化源文件的顺序；失败或取消时保留源数据，回退本次产生且未被修改的副本。已有相同内容允许重试，不覆盖不同内容；不使用 legacy 的目录扁平化规则。
- 链接和路径边界：根目录、祖先及内部文件/目录链接均不跟随；增加实际文件系统重叠检查，覆盖大小写和 Windows 短路径别名。复制进度按实际字节，校验、保存配置、清理阶段明确显示阶段文字。
- 现场文件中的 OriginalPath 不再序列化或信任；加载后只能使用本次从 ZIP 解出的截图。引用缺失、保存源图缺失时明确失败，保留已有归档；部分解压文件纳入失败清理。
- 关闭保存：不保存才允许明确放弃；取消选择保存位置、关闭询问框或保存失败都保留窗口和数据，下一次关闭仍询问。
- CSV 秒级 FrameTime Mean 按帧数加权；多窗口无法获得帧数时显示缺测。整秒无法从窗口 P95 反推真正 P95，列名改为 WindowP95Max，原始明细的 P95 不变；曲线、采集及现场原始数据不变。
- macOS 自定义数据目录在 Application Support 中持久化，重启读取；兼容旧 bundle 配置并迁到外部稳定位置，自动迁移不触碰配置或包含目标的目录。

## 回滚

跨平台版本使用独立目录和应用标识。任何阶段失败均可继续使用 `dist/backups/MoTuPerf-v0.4.65-baseline/` 中的源码和安装包恢复 Windows 版本。

## v0.24.2 实现与验证

- 增加 generation 隔离的 UI 样本队列，250ms 合批通知；停止排空已接受样本，拒绝迟到通知。每轮新建采集及截图服务，后台任务完成后再释放日志。
- 日志新增任务生命周期、真实指标更新接收时间及停止摘要；检测状态使用在线/离线/未知，不把探测失败当拔线。
- SampleSnapshot 公开只追加列表的固定前缀并共用有序视图；最近样本按有序索引查找；曲线缓存与游标分离，使用几何路径和线性极值投影。
- Android/iOS 发现结果保留基本设备与详情失败诊断；UI 使用独立、可换行的诊断区域。
- 同机 10 万条模拟样本基准：追加 200 条从 v0.24.1 的 4490.7ms/153.98MB 分配降为 1.7ms/0.60MB；50 次游标重绘从 2849.8ms/2410.79MB 分配降为 8.7ms/4.96MB。这是测试线程累计分配和模拟操作耗时，不能等同整机内存或真机采集速度。
- 自动回归与三主题截图见 Trellis 任务 `09-17-capture-reliability-performance`；原始保存样本数、极值、零值、缺失与固定选中时间均有回归。macOS 和长时间真机采集另行验收。
