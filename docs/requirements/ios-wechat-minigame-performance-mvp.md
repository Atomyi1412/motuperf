# iOS 微信小游戏性能采集 MVP

Status: implemented
Related implementation: [implementation/ios-wechat-minigame-performance-mvp.md](../implementation/ios-wechat-minigame-performance-mvp.md)

## 背景

测试人员需要一个比 PerfDog/Gears 更轻量的本地工具，用 USB 连接 iOS 设备，观察应用和微信小游戏运行时的实时帧率、卡顿和内存变化，并把数据导出到本地用于复盘。

当前仓库为空，尚无现有应用代码。`trellis-codex-workflow` 技能包已安装并写入 `AGENTS.md` 工作流块，相关脚本已复制到 `scripts/`。该技能包不是 Trellis CLI 本体，`.trellis/` 尚未初始化。

## 目标

- 提供一个可在本机运行的第一版性能采集软件。
- 支持 USB 模式连接 iOS 设备。
- 支持测试 iOS 应用以及微信小游戏运行场景。
- 实时展示 FPS、Jank、BigJank 和内存曲线。
- 支持开始、停止采集，并将采集数据导出到本地。

## 非目标

- 不做 Wi-Fi 模式、云端设备池、远程采集或多人协作。
- 不做多设备并发采集。
- 不做 CPU/GPU/网络/温度/电量/日志等完整 PerfDog/Gears 指标。
- 不做自动启动微信小游戏、自动化脚本录制、深度报告、AI 分析或历史对比。
- 不要求第一版覆盖所有 iOS 版本；必须对不支持的系统或依赖缺失给出清晰提示。

## 术语

- **USB 模式**: 设备通过 USB 连接到本机，由本机工具读取 iOS 设备和目标进程性能数据。
- **微信小游戏性能**: 在 iOS 设备上打开微信并运行指定小游戏时，采集微信宿主进程及系统可见渲染性能数据。
- **目标进程**: 采集工具绑定的 iOS bundle 或进程，微信小游戏第一版默认 `com.tencent.xin`。
- **实时曲线**: 采集期间持续追加刷新 FPS、Jank、BigJank 和内存数据的时间序列视图。
- **本地导出**: 将一次采集的原始采样和基础汇总保存到本机文件。

## 范围

### 包含

- 设备连接状态展示。
- 目标 bundle 输入，默认值为 `com.tencent.xin`。
- 采集控制：开始、停止、清空。
- 实时数值卡片：当前 FPS、Jank、BigJank、内存。
- 实时曲线：FPS/Jank/BigJank 同图，内存单独曲线。
- 本地导出：CSV 必须支持，JSON 可选。
- 无真实设备或后端不可用时，提供清晰错误提示；开发期可保留模拟数据模式用于界面验证。

### 不包含

- 自动列出和启动微信小游戏。
- 采集小游戏独立进程级别数据。
- 采集 Android、Windows、macOS 或其他平台。
- 采集和分析 CPU、GPU、网络、温度、电量、Wakeups。
- 云端保存、账号体系、权限体系、团队项目。

## 需求

- 工具必须能在 Windows 本机启动。
- 工具必须提供一个桌面或本地网页界面，第一屏就是采集操作台。
- 用户必须能输入或选择目标 bundle；微信小游戏场景默认 `com.tencent.xin`。
- 用户必须能点击开始采集，看到采集状态、运行时长和实时曲线刷新。
- 用户必须能点击停止采集，停止后保留本次数据。
- 用户必须能把本次采样导出为 CSV，字段至少包括时间戳、相对秒数、FPS、Jank、BigJank、内存 MB、数据来源和备注。
- 若 USB 设备、iOS 信任、iTunes/Apple Mobile Device 支持、采集依赖或 iOS 版本不满足要求，工具必须显示可理解的排查提示。
- 若真实采集后端暂不可用，模拟数据模式必须在 UI 上明显标识，不能伪装成真实设备数据。

## 验收标准

- [x] 本机能启动工具界面。
- [x] 默认目标显示为 `com.tencent.xin`。
- [x] 点击开始后，FPS/Jank/Memory 曲线会实时追加数据。
- [x] 点击停止后，采集停止且数据仍可查看。
- [x] CSV 导出文件能在本地生成，并包含采样明细。
- [x] 无真实设备环境下，工具能以模拟模式完成界面和导出验证，并明确标识“模拟数据”。
- [x] 真实 iOS USB 后端接入后，工具能通过命令或 UI 看到真实采样来源；当前机器缺少 `pyidevice`/`tidevice`，已验证缺依赖提示。

## 边界和异常

- iOS 上微信小游戏通常运行在微信宿主环境中，第一版默认采集微信宿主进程或系统显示数据，不承诺识别具体小游戏进程。
- iOS 17 及以上设备可能需要额外隧道、开发者模式或不同采集后端；第一版必须给出提示。
- Jank/BigJank 优先使用采集后端直接返回的数据；如果后端不提供，不应把简单 FPS 波动冒充为精确 Jank。
- 内存指标名称必须标注来源，例如 Memory、Footprint 或 PSS-like，避免和 Android PSS 混淆。

## 已确认决策

- 第一版把“微信小游戏性能”定义为：用户手动在微信中打开小游戏后，工具默认采集 `com.tencent.xin` 微信宿主进程和系统可见 FPS/Jank/Memory，而不是追求独立小游戏进程识别。
