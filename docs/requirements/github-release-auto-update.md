# GitHub 自动发布与客户端更新需求

## 状态

confirmed

## 背景

MoTuPerf 需要将源码放到 GitHub 公共仓库中，并在每次版本发布时自动生成可分发安装包。客户端可以按用户设置检查新版本，在有新版本时给出提示，并允许用户下载对应平台的安装包。

## 目标

- 使用公开仓库 `https://github.com/Atomyi1412/motuperf` 保存源码、文档和构建配置。
- 推送符合 `v主版本.次版本.修订版本` 的版本标签后，自动运行测试并构建发布产物。
- 发布 Windows x64 安装包和 macOS Apple Silicon 安装包。
- 客户端提供是否检查更新的设置；关闭后不主动弹出更新提示。
- 检测到新版本时显示版本号、更新说明和发布时间，用户确认后下载当前系统对应的安装包。
- 下载完成后校验文件完整性，并进入平台对应的安装流程。

## 一期：自动构建与发布

### 触发方式

- 推送版本标签 `v*` 触发 GitHub Actions。
- Pull Request 和主分支提交执行编译、单元测试及静态检查，但不发布正式安装包。
- 发布任务只使用仓库内锁定的依赖和现有 Windows/macOS 打包脚本。

### 发布产物

- Windows：`MoTuPerf-Setup-vX.Y.Z.exe`。
- macOS Apple Silicon：`MoTuPerf-vX.Y.Z-osx-arm64.dmg`。
- 每个产物生成对应的 SHA-256 文件。
- Release 同时包含机器可读的 `latest.json`，记录版本号、更新说明、发布时间、平台、架构、下载地址和 SHA-256。

### 发布门禁

- 测试或构建失败时不得创建正式 Release。
- 版本标签、项目版本号、安装包文件名和 `latest.json` 版本必须一致。
- 不向仓库提交本地日志、现场文件、用户数据、运行时生成目录、访问令牌或其他密钥。
- 自动构建使用最小权限；工作流不得把密钥写入构建日志或安装包。

## 二期：客户端检查与更新

### 检查策略

- 设置中增加“检查更新”开关，默认开启。
- 客户端启动完成后异步检查公开 GitHub Releases 清单，不阻塞主界面、设备发现和采集功能。
- 网络失败、GitHub 暂时不可用或清单格式错误时只记录日志，不影响软件正常使用。
- 采集、打开、保存、导出或数据迁移进行中不弹出更新安装操作；检查结果可以延迟到当前操作完成。
- 更新提示提供“更新”“稍后提醒”和“跳过此版本”选项，避免重复打扰。

### 下载与安装

- 只接受清单中声明的 HTTPS GitHub Release 资产，不下载分支源码压缩包。
- 按当前操作系统和 CPU 架构选择产物；不匹配时不允许下载。
- 下载到临时文件，完成后校验 SHA-256，校验失败删除临时文件并提示失败。
- Windows 下载完成后可启动对应安装包；macOS 下载完成后打开 DMG，由用户完成替换安装。
- 更新程序或安装包启动前关闭当前应用；采集状态未结束时禁止更新。
- 更新失败时保留旧版本可启动，不能删除用户数据目录、现场文件、日志和配置。

### 版本判断

- 使用三段数字版本比较，不按字符串比较。
- 当前版本低于清单版本才提示更新。
- 清单版本为空、格式非法或高于当前应用可识别范围时不执行更新。
- 只允许稳定版本，不自动接受预览版或其他分支版本。

## 明确不做

- 不在客户端嵌入 GitHub 个人访问令牌。
- 不把用户现场文件、日志或设备信息上传 GitHub。
- 不在采集过程中强制更新、重启或关闭软件。
- 不实现后台静默安装、自动回滚服务器或多渠道升级系统；先保证公开 Release 下载和本地安装可靠。

## 验收标准

- GitHub Actions 能在模拟版本标签下完成测试、Windows 构建和 macOS arm64 构建；失败任务不会发布 Release。
- Release 中的两个安装包、校验文件和 `latest.json` 版本一致，且下载后校验通过。
- 客户端关闭检查更新后不发起主动检查；打开后能识别新版本并显示提示。
- 更新检查失败不影响启动和采集。
- 用户确认更新后，只下载当前平台资产，校验通过后进入正确安装流程。
- 用户取消、跳过、下载失败、校验失败、采集中点击更新时，软件状态和用户数据保持不变。
- Windows 和 macOS 分别完成安装包启动验证；真实跨电脑设备采集仍作为发布后的验收项，不由 CI 替代。

## 已确认的发布边界

- 公共仓库由 `Atomyi1412` 维护，仓库名为 `motuperf`；首次创建和授权 GitHub Actions 需要在 GitHub 账号侧完成。
- macOS 首期采用“自动下载 DMG 后打开，由用户拖入 Applications”方式；暂不做静默替换安装。
