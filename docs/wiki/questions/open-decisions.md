Status: confirmed

### 决策 1: 微信小游戏性能边界

推荐选择：第一版把“微信小游戏性能”定义为用户手动在微信中打开小游戏后，工具默认采集 `com.tencent.xin` 微信宿主进程及系统可见 FPS/Jank/Memory。

理由：

- iOS USB 外部采集不一定能稳定识别独立小游戏进程。
- 该定义能覆盖测试人员关心的实际运行体验。
- 后续如果有稳定进程识别或微信小游戏调试协议，再扩展小游戏级绑定。

### 决策 2: 第一版实现形态

推荐选择：第一版采用“本地 Web 操作台 + Python 后端”。

理由：

- 当前仓库为空，本地 Web 操作台最快能交付可运行 MVP。
- Python 后端便于接入 `py-ios-device`、`tidevice` 或其他 iOS USB 采集工具。
- 后续可以在稳定后再封装为 Windows 桌面应用或 exe。
